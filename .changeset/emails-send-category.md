`CodeEmail` takes a `Category`, so code can send marketing email and file email under a message category. Set it to `posthog.MessageCategory{Key: "newsletter", Type: posthog.MessageCategoryMarketing, Name: "Newsletter"}`, which defines the category in code: the first send with a `Key` creates the category with its `Name` and `Description`. Later sends keep its name and description, so change them in PostHog. Leave `Category` out for transactional email with no category, as before, or, when code-send categories are enabled for the project, for the transactional category of the template that `TemplateKey` names (when categories are disabled for the project, the email is queued as transactional with no category). An explicit `MessageCategory` returns `categories_not_enabled` when categories are unavailable for the project (and HTTP 400 on an older server). `posthog.EmailCategoryTransactional` asks for transactional email with no category, so PostHog refuses it with `category_mismatch` on a template in a transactional category (and `marketing_template` on a template in a marketing category). A marketing send honors the recipient's opt-outs, can't have `Cc` or `Bcc` (`copies_not_allowed`), can't carry attachments (`workflow_can_wait`, because marketing sending limits can hold delivery), and needs a clickable `<a href="{{ unsubscribe_url }}">` link in `HTML` (or `{{ unsubscribe_url }}` in `Text` when there is no `HTML`). PostHog refuses such sends with `categories_not_enabled`, `category_mismatch`, `too_many_categories`, `unsubscribe_link_required`, `copies_not_allowed`, `workflow_can_wait`, or `recipient_opted_out`. A template made in PostHog sends transactional email only, so PostHog refuses a `TemplateEmail` of a template in a marketing category, or a `CodeEmail` whose `TemplateKey` names one, with `marketing_template`.
