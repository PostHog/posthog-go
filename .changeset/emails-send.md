Add `Client.Emails()` to send transactional email and read its status. `Send` takes a `TemplateEmail`, a template made in PostHog sent by its ID with `TemplateData`, or a `CodeEmail`, content your code rendered and named by a `TemplateKey`, with `Subject`, `HTML` and/or `Text`, `From`, `ReplyTo` and `CaptureEngagement`. `Get` reads an email's status by its message ID. Both need `Config.SecretKey`, a project secret API key with the `transactional_email:write` scope (`Get` also accepts `transactional_email:read`), and go to the PostHog app host: `Config.AppHost`, or the app host of a PostHog Cloud `Endpoint`. `AppHost` must use https unless `Config.AllowInsecureAppHost` is set, such as for http://localhost:8010 during local development. When `AppHost` is set, local flag definitions and remote config payloads also go there, so a reverse proxy at `Endpoint` never gets the secret key. Every send carries an idempotency key, and network errors, rate limits and an unavailable service are retried with it (`Config.EmailRequestMaxRetries`, default 2). Errors are `*EmailError` values with PostHog's `Code` and a coarse `Name`. `Close` waits for email requests in flight. New `Config` options: `AppHost`, `AllowInsecureAppHost`, `EmailRequestTimeout`, `EmailRequestMaxRetries` and `MigratedFrom`.

`Client` gains the `Emails` method, so a type that implements `Client` itself needs it too.
