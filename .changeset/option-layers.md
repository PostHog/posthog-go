Add `Config.DefaultEventOptions` and `RequestContext.Options`, so capture options can be set for every event and for a request. Request-context values, `Config.DefaultEventProperties` and `Config.DefaultEventOptions` now fill in after `BeforeSend`, only for keys the event and the hook left unset; in 1.x a default property overwrote the event's value and `BeforeSend` saw it. `BeforeSend` no longer sees request-context or default values, so set a key on the event or in the hook to override them. A `nil` option counts as unset, so the default still fills it. `DefaultEventProperties` and `DefaultEventOptions` now also apply to `Exception`, `Identify`, `Alias` and `GroupIdentify` events, as event properties and options, never in `$set` or `$group_set`. The SDK's personless default and `posthogmcp`'s person opt-out are now sent as the `process_person_profile` option. A default, request-context or event option can override the personless default; a legacy `$process_person_profile` property cannot. `posthogmcp.ToolCall` and `posthogmcp.EventContext` gain an `Options` field, and every `posthogmcp` event takes `RequestContext.Options`. With a `posthog.Client`, `posthogmcp` events take the sanitized request-context properties and options after `BeforeSend`, like any capture. Minimal `$feature_flag_called` events now keep `$cookieless_mode`, `$ignore_sent_at` and `$product_tour_id`, so they still become options. See `docs/migration-v2.md`.
