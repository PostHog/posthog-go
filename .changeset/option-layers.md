Add `Config.DefaultEventOptions` and `RequestContext.Options`, so capture options can be set for every event and for a request. Request-context values, `Config.DefaultEventProperties` and `Config.DefaultEventOptions` now fill only keys the event left unset, before `BeforeSend`; in 1.x a default property overwrote the event's value. `BeforeSend` sees the filled values and can change or remove them. `$set`, `$set_once`, `$groups` and `$group_set` fill one level deep when both values are maps, and `Capture.Groups` merges into a `$groups` map key by key. A `nil` option counts as unset, so the default still fills it. `DefaultEventProperties` and `DefaultEventOptions` now also apply to `Exception`, `Identify`, `Alias` and `GroupIdentify` events. `Identify`, `Alias` and `GroupIdentify` gain an `EventProperties` field for the event's own properties, which the defaults fill. The SDK's personless default and `posthogmcp`'s person opt-out are now sent as the `process_person_profile` option. A default, request-context or event option can override the personless default; a legacy `$process_person_profile` property cannot. `posthogmcp.ToolCall` and `posthogmcp.EventContext` gain an `Options` field, and every `posthogmcp` event takes `RequestContext.Options`. `posthogmcp` events take the sanitized request-context properties and options under the call's own, with any client. Minimal `$feature_flag_called` events now keep `$cookieless_mode`, `$ignore_sent_at` and `$product_tour_id`, so they still become options. See `docs/migration-v2.md`.
